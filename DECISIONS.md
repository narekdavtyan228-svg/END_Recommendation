## Контракты и API

- 2026-10-06 · 4 · Идентификаторы прогонов и находок — UUID без префиксов `r_`/`f_`. · Столбцы БД — `uuid`.
- 2026-10-06 · 4 · `Idempotency-Key` обязан совпасть с `end.contentHash`, а тот — с хешем, пересчитанным сервером (иначе 422 `content_hash_mismatch`). · Шлюз сравнивает хеши; подложный хеш в теле обошёл бы его.
- 2026-10-06 · 4 · Повтор того же (endRef, contentHash, пакет правил) возвращает готовый прогон с кодом 200 (не 409 `run_exists`). · Раздел 4 ТЗ имеет приоритет над таблицей кодов архитектуры.
- 2026-10-06 · 4 · Хеш считается по проверенной модели до очистки и маскирования; значения по умолчанию — `[]`/`null`; сортировка по `section` — строковая (`5.10` < `5.2`). `answers`: хеш пересчитывается по сохранённому (уже очищенному) снимку; при ИИН/HTML в исходном тексте HSE считает хеш по маскированному тексту либо шлёт новый `POST /v1/checks`. - 2026-10-06 · 4 · Режим А: `requestedBy` перезаписывается из токена; доступ к чужому прогону/находке — 404; лимит прогонов считается по таблице `check_run`; для сервисного токена 600 в час на весь сервис.
- 2026-10-06 · 4 · Ошибки: невалидный JSON — 400 `schema_invalid`; нарушение схемы — 422 `validation_failed` с путём поля (без значений).
- 2026-10-06 · 4 · Действия: `hide` запрещено для критичных находок; `answer` — только для вопросов; «обработаны» для критичных — `accept`, `edit`, `reject`; для блокирующих вопросов — `answer`. Тексты блокеров шлюза — собственные короткие (`runs.BLOCKER_TEXT`).
- 2026-10-06 · 4 · `/v1/gate` и `/v1/catalog/version`, `/v1/sync` — только сервисный токен.
- 2026-10-06 · 4 · Ограничение тела и `X-Request-Id` реализованы ASGI-прослойкой (`api/asgi.py`) — единственное место с `async def`; `make sec` разрешает `async def` только в этом файле. · Размер тела нельзя ограничить в синхронном обработчике до чтения тела.
